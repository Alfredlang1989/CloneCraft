# M10 contract - Hierarchical fast travel

## Purpose

Restore exact hierarchy-aware camera jumps for worldgen/debug exploration,
using the current coordinate, DynamicSpace, render-anchor, streaming and
selection contracts. A jump changes one selected hierarchy digit while
preserving all lower digits and sub-block fractions where applicable.

M10 is a navigation milestone of its own. It must not be folded into M04-M08
or the completed worldgen baseline.

## Controls

| Input | Exact jump |
|---|---|
| Arrow | 1 block |
| Ctrl + Arrow | 1 chunk |
| Alt + Arrow | 1 chunk group |
| Shift + Arrow | 1 section |
| Ctrl + Alt + Arrow | 1 region |
| Ctrl + Alt + Shift + Arrow | 1 sector |

Left/right affect X and up/down affect Z. Unassigned modifier combinations are
rejected without movement. While an arrow jump chord is active, Shift must not
also trigger normal camera descent.

## Exact coordinate operation

The coordinate layer owns a checked operation equivalent to:

```cpp
bool tryOffsetHierarchy(const BlockAddress &base, HierarchyLevel level,
                        std::int64_t dx, std::int64_t dy, std::int64_t dz,
                        BlockAddress &out) noexcept;
```

For Block, use the existing digit-by-digit block offset. For Chunk, Group,
Section and Region, modify that digit, normalize carry/borrow outward, and
preserve every lower digit. For Sector, perform checked signed-int64 addition.
Any outer overflow returns false and leaves the live camera/world state
unchanged. No implementation may flatten the address or compute an
astronomical float/double delta.

## Atomic jump integration

One owner-thread jump transaction performs all of the following coherently:

1. snapshot the exact current `WorldPosition` and fractional X/Y/Z;
2. compute the checked target `BlockAddress`;
3. on success, move the `WorldDynamicBridge` exact anchor to the target block;
4. retain only the preserved sub-block fraction in local camera space;
5. teleport/update the sticky render anchor and both world/selection renderers;
6. update streaming demand around the target and safely retire or ignore stale
   work from the previous residency window;
7. recompute or clear block selection against the target location;
8. refresh camera pose and debug HUD from the same resulting address.

On rejection, none of those states changes. Future dynamic objects/Jolt bodies
must join the same DynamicSpace transaction; do not special-case an absolute
camera coordinate that cannot later be generalized.

## Mandatory proofs

1. every hierarchy level preserves all lower digits and all untouched axes;
2. positive carry and negative borrow cross every digit boundary correctly;
3. minimum/maximum Sector overflow is rejected with no partial X/Y/Z update;
4. sub-block fractions survive jumps at huge hierarchy addresses;
5. the control mapping above is exact for left/right variants and both common
   left/right modifier keys;
6. arrow + Shift performs only the Section/Sector chord action and never normal
   descent in the same frame;
7. after a jump, bridge anchor, camera local position, render anchor, streaming
   center, selection and HUD describe the same exact world position;
8. old-location queued streaming work cannot repopulate the active residency
   set incorrectly after a huge jump;
9. rejected overflow/unassigned chords leave every integration surface
   unchanged;
10. no global flattened integer, absolute double position or unbounded float
    jump is introduced;
11. coordinate, DynamicSpace, streaming, interaction and rendering regressions
    remain green;
12. the independent reviewer gate `./compile.sh` passes on the target
    environment, followed by a human jump/inspection gate.
