# M08 contract - Construction blueprints and jobs

## Purpose

Build blueprint selection, compact representation, ghost/status evaluation and
construction jobs on top of M07. M08 must not create a second geometry or world
writer architecture.

## Blueprint model

A blueprint has stable logical identity plus at minimum:

- anchor/origin and transform/orientation contract;
- bounds;
- compact shape/operation representation using M07 primitives;
- material/content references using stable namespaced identity at durable
  boundaries;
- optional metadata that is content-defined rather than hard-coded gameplay
  concepts in generic C++.

A/B selection may define capture bounds/anchors, but captured output is
normalized to the same blueprint representation.

## World comparison

Blueprint evaluation derives status from authoritative WorldState:

- missing;
- fulfilled;
- conflict.

These are derived planning states, not a second authoritative voxel store.
Comparison must work incrementally/bounded for large blueprints rather than
requiring an unbounded all-world scan each frame.

## Ghost rendering

Ghost rendering is client/presentation projection of blueprint evaluation. It
never becomes authoritative and never owns construction completion state.
Renderer consumes generic blueprint/status data, not game-specific building
semantics.

## Construction jobs

A Construction Job references blueprint + anchor/transform and tracks bounded
work/tasks. Resource requirements are data/content driven.

The executor is generic. It consumes bounded tasks and submits/applies work via
the same M07 writer and authoritative communication/server path. No separate
"blueprint setBlock" implementation.

Jobs must have explicit lifecycle/cancellation/retry state suitable for M05
persistence and M06 server authority. Task identifiers are stable logical IDs,
not process handles.

## Performance and bounds

Large blueprints are represented compactly and expanded/evaluated in bounded
chunks/tasks. Do not allocate one heavyweight persistent object per target
voxel unless a measured requirement justifies it and the architecture contract
is updated deliberately.

## Mandatory proofs

1. blueprint geometry reuses M07 Shape/Writer public spine;
2. A/B capture or constructed blueprint round-trips anchor/bounds/shape data
   deterministically;
3. missing/fulfilled/conflict classification matches WorldState for a mixed
   test blueprint;
4. ghost rendering consumes derived status and cannot mutate authoritative
   state;
5. construction job decomposes a large blueprint into bounded tasks;
6. executor applies tasks only through M07 + server/WorldState authority;
7. resource requirements are content/data driven, not hard-coded building
   semantics in generic engine code;
8. cancellation/retry does not duplicate fulfilled work or corrupt progress;
9. persistent job/blueprint identity contains no raw ECS/Jolt/Ogre/process
   handles;
10. large blueprint path does not require one Lua call or network envelope per
    target voxel;
11. architecture rules classify blueprint/job dependencies and prevent a second
    geometry/writer path;
12. M01-M07 regressions remain green and reviewer `./compile.sh` passes.

## Required references

- M07 contract and resulting Shape/Writer API
- M05 persistence boundary
- M06 server/transport authority
- renderer docs only for ghost rendering implementation
