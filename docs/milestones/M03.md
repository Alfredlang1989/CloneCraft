# M03 contract - Router, gameplay Lua, scheduler and integrated bus proof

## Goal

Close the communication/runtime foundation as one integrated architecture:
router + bounded queues/contracts + owner-thread gameplay Lua + delayed message
scheduler + a real two-block content proof using the same public mechanisms.

M03 R1-R3 behavior is established baseline. The current work is closure of the
integrated proof and review findings, not a redesign of accepted router,
scheduler or Lua semantics.

## Required architecture

- obey `docs/ARCHITECTURE.md` completely;
- one CommunicationEnvelope/runtime/router only;
- WorldState remains sole gameplay world-mutation authority;
- scheduler stores plain envelopes and worker never runs gameplay/Lua/WorldState;
- Lua reads world state through approved API and mutates by bus commands;
- proof-specific game/content semantics live in data/Lua, not generic C++;
- envelope fields keep their permanent meaning, especially `replyTo`;
- application proof wiring must respect normal world materialization/streaming;
- renderer proof visualization must be generic and resolve the correct block on
  every face direction.

## Repair closure mechanics

- `MODS/Default/gameplay.json` is the shipped source of script, route,
  placement and initial-invocation data; production C++ owns only the generic
  loader/runtime;
- peer coordinates use `BlockTargetPayload`; `replyTo` remains reply
  correlation only;
- logical mutations use the registered generic `core:property.set` command and
  WorldState validation;
- bootstrap execution waits for normal streaming/worldgen materialization.
  Content may explicitly declare `replaceOccupied`; replacement then uses the
  normal remove command followed by the normal place command;
- block registry data may name a generic packed-uint32 visual tint property;
  mesh output records each quad's emitting voxel for exact six-face lookup.

## Integrated proof

Two content-defined blocks A and B are placed in a normally materialized world
location.

Block A:

1. starts via the normal runtime integration;
2. schedules an envelope to itself after 5 real seconds;
3. on each callback updates sparse logical state through the bus/WorldState;
4. alternates a visible state and increments a callback counter;
5. repeats until exactly six callbacks occurred;
6. then emits exactly one Event addressed to B.

Block B:

- has its own Lua/content handler;
- receives A's Event through the same router;
- changes its own visible logical state through the normal command/WorldState
  path;
- is never called directly by A-specific C++.

Automated tests use TestClock/fake time. Machine-testable semantics must be
proven without sleeping 30 seconds.

Final human visual gate after machine acceptance:

- normal generated terrain is visible at the proof location;
- A visibly alternates state at approximately 5-second intervals for exactly
  six callbacks;
- after callback six B changes exactly once through its own handler;
- no crash, empty fake terrain chunk or direct A->B shortcut is involved.

The harness reviewer returns `PASS_AWAITING_MANUAL` when this is the only
remaining gate.

## Acceptance criteria

1. All known blockers in `docs/ACTIVE_FINDINGS.md` are closed by code/diff.
2. No proof-specific `test:*`, A/B or red/green content semantics remain in
   generic production C++ unless a value is merely opaque data consumed by a
   generic registered mechanism.
3. `replyTo` is used only as a logical reply address.
4. Scheduler callback chain is exactly six and stores/transports no callbacks,
   function pointers or Lua refs.
5. A -> B is exactly one routed Event; no direct A -> B C++ call.
6. WorldState is the only authoritative mutation path used by the proof.
7. Proof placement does not suppress/replace normal worldgen materialization.
8. Visual-state lookup resolves the emitting block for all six face directions.
9. Acceptance automation exercises shipped Lua/content rather than a divergent
   embedded copy.
10. Unrelated generated shader-cache files are absent from the candidate diff.
11. Existing M03 router/scheduler/gameplay-Lua regression suites remain green.
12. Reviewer final gate `./compile.sh` passes on the target environment.
