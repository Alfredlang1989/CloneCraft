# M07 contract - Construction foundation

## Purpose

Create one reusable shape + bulk-writer spine for construction without turning
Lua into a 10,000-call voxel loop and without bypassing WorldState/communication
validation.

## Separation of concerns

Geometry answers "which relative cells belong to this shape?".
Writer answers "how is this validated and applied to world state?".

Keep those layers separate so M08 blueprints can reuse exactly the same geometry
and writer.

Initial generic shapes include at minimum:

- line;
- floor/filled rectangle;
- wall;
- filled box;
- hollow box;
- at least one curved shape represented generically (for example arc/circle/
  cylinder family chosen by the implementation plan).

Shapes are engine-generic geometry, not building/game semantics.

## Bulk mutation

Provide get/set/setBulk-style capability through the approved architecture.
Large construction operations cross Lua/C++ and client/server boundaries as
compact operation data, not one call/message per block.

Bulk application must:

- validate canonical hierarchical addresses and overflow;
- handle chunk boundaries correctly;
- respect block/property registry validation;
- preserve WorldState as authoritative mutation owner;
- produce bounded/coalesced dirty/invalidation work rather than one expensive
  rebuild notification per cell where safe;
- define partial-failure/atomicity semantics explicitly.

Player placement remains a normal Communication Command. Construction does not
create a privileged mutation channel.

## Lua/data interface

Lua may describe/select a registered generic shape and parameters. Lua does not
receive raw ChunkManager or loop through direct C++ setters for each voxel.

Game-specific building types/material meaning remain content logic.

## Performance contract

A 100x100 floor (10,000 blocks) must not require 10,000 Lua -> C++ calls or
10,000 independent gameplay envelopes. The writer may internally touch cells,
but boundary overhead and invalidation are bulk-aware.

## Mandatory proofs

1. each required shape produces deterministic expected cell sets;
2. shape generation is independent from world mutation/writer;
3. 100x100 floor uses one/bounded compact API operation across Lua/C++ boundary;
4. bulk write crossing multiple chunks produces correct blocks and bounded
   dirty/invalidation per affected region/chunk according to the chosen design;
5. invalid address/overflow/registry input is rejected without silent partial
   corruption;
6. defined partial-failure/atomicity behavior is tested;
7. construction still enters authoritative mutation through the communication/
   WorldState spine;
8. no second geometry implementation is embedded in writer/UI/Lua;
9. no game-specific building semantics enter generic C++ geometry;
10. M08 can consume the public Shape/Writer interfaces without redesign;
11. architecture rules classify construction module/dependencies;
12. M01-M06 regressions remain green and reviewer `./compile.sh` passes.
