# M06 contract - Embedded client/server and transport boundary

## Purpose

Make the server authoritative even in standalone play while preserving the one
CommunicationEnvelope semantics created in M02/M03.

Standalone becomes client + embedded server, not a privileged direct-to-world
mode.

## Authority

Server owns:

- authoritative WorldState;
- coordination of hot ECS projection;
- persistence;
- authoritative gameplay command validation/execution.

Client owns input/presentation and client-side caches/projections. Client code
cannot mutate server WorldState merely because it shares a process.

## Sessions and transport

Provide explicit ClientSession / ServerSession (names may vary if semantics are
identical) over a transport interface.

First transport is deterministic InProcess/Loopback. The interface must be
usable by a future TCP/network transport without changing gameplay message
semantics.

Transport carries the existing CommunicationEnvelope wire contract including
sender, receiver, context, action, target, payload, message ID,
correlation/reply semantics and capability/security metadata required by the
runtime.

Do not invent a parallel gameplay `NetworkMessage` model. Framing/connection
control may have transport-internal packets, but gameplay content enters/leaves
as the same envelope contract.

## Serialization

The strict envelope codec is the transport boundary. No pointers, Lua refs,
callbacks, `entt::entity` or process-local handles cross it.

Malformed/unknown payloads fail cleanly. Message IDs/correlation semantics are
preserved end to end and are not regenerated arbitrarily by the transport.

## Threading and backpressure

Transport/network workers do I/O only. They hand decoded envelopes to server or
client owner-thread queues. They do not execute gameplay handlers or mutate
WorldState.

Queue bounds/backpressure/disconnect behavior are explicit. A slow client must
not create unbounded server memory.

## Standalone invariant

The normal singleplayer path must exercise the same client -> transport ->
server -> CommunicationRuntime -> WorldState authority path that a remote
client would logically use.

No "if local then call WorldState directly" shortcut.

## Mandatory proofs

1. M02 place/remove command travels client -> loopback -> server and mutates only
   server-authoritative WorldState;
2. representative M03 Event/Query/Reply semantics survive loopback with exact
   target/payload/message/correlation meaning;
3. client cannot directly obtain/use mutable authoritative WorldState path;
4. serialization rejects malformed/unsupported envelopes deterministically;
5. no raw ECS/renderer/physics/process handles cross transport;
6. bounded transport queues/backpressure behavior is tested;
7. disconnect/shutdown leaves no worker touching destroyed server/client state;
8. at least two logical sessions can be distinguished without sender identity
   collision;
9. InProcess transport and future network transport share one gameplay codec;
10. architecture rules prevent transport/network layer from becoming a second
    world-state implementation;
11. standalone application actually wires through embedded server path;
12. M01-M05 regressions remain green and reviewer `./compile.sh` passes.
